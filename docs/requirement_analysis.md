# 产品需求文档 (PRD)：AI 辅助四格漫画全自动生成系统

## 一、 产品概述
本系统旨在打造一个由 AI 多智能体（Multi-Agent）驱动的四格漫画生产管线。通过结合大语言模型（LLM）的逻辑编排能力与先进图像生成模型（以 Google **Nano Banana 2 / Gemini 3 Flash Image** 为核心驱动）的视觉与原生文本生成能力，辅助创作者快速完成从角色设定、剧本分镜到图像生成与排版的全流程商业级漫画创作。系统强调“人机协同（Human-in-the-Loop）”与“低成本试错”，同时提供高度的兼容性以适应不同的内容分发需求。

## 二、 核心业务流程（用户视角）
1. **资产准备：** 用户选择系统内置的“角色资产库”或新建角色，自由搭配预设服装与道具。
2. **模式与灵感输入：** 用户选择创作模式（独立四格小剧场 vs. 长线连载四格），并输入情景梗概或连载大纲。
3. **剧本与分镜确认：** AI 自动生成剧本与分镜后，进入“聊天式动态预览（Previz）”界面。
4. **人工干预 (HITL)：** 用户在直观的 UI 中预览剧情走向，修改台词、调整机位、或要求重写单格/调整连载节奏。
5. **渲染生成设置：** 用户确认分镜无误后，选择输出模式（AI 直接嵌字版 / 无字净版），点击一键渲染。
6. **成片交付：** 系统完成图像生成与后期合成，输出带排版的高清四格漫画，或输出分层素材以供其他模型及人工后期使用。

## 三、 系统架构与多智能体管线 (Pipeline)

系统底层由 4 个阶段、8 个专门的 AI Agent 协作构成：

### 阶段一：剧本与设定生成 (Text Pipeline)
* **Agent 1 - 设定主笔 (Character Agent)：** 负责角色检索与实例化。调取数据库中的角色基础设定与服饰扩展槽位，拼接完整的性格与视觉 Prompt。
* **Agent 2 - 剧本总监 (Scriptwriter Agent)：** 具备双模式剧本输出能力。对于“四格小剧场”，输出单次完整的“起、承、转、合”结构；对于“连载四格”，则根据长线剧情大纲，将其切分为以 4 格为单位的连载单元，确保每一话有合理的悬念或笑点收尾。
* **Agent 3 - 分镜导演 (Storyboard Agent)：** 将剧本翻译为机器可读的 JSON 脚本，包含镜头景别、画面主体、正负向提示词、台词文本及排版坐标等。

### 阶段二：交互式预览与干预 (Previz & HITL Checkpoint)
* **纯前端渲染模块：** 拦截“分镜导演”输出的 JSON，渲染为带有头像、对话气泡、旁白和镜头指示的 UI 界面，供用户低成本审阅和修改。

### 阶段三：图像生成与品控 (Image Pipeline)
* **Agent 4 - 视觉资产管家 (Asset Manager)：** 统筹视觉一致性，分发参考图、固定的 Seed 以及风格控制指令，管理角色视觉连贯性。
* **Agent 5 - 主笔画师 (Generation Engine)：** 核心驱动为 Nano Banana 2。执行图像生成任务。根据输出需求，决定是否在提示词中激活“原生文本渲染”指令。
* **Agent 6 - 质量审校组长 (QC Reviewer Agent)：** 利用多模态视觉模型，对比分镜脚本与生成的图像，剔除明显幻觉（如肢体扭曲、关键特征丢失或 AI 拼写错误），并触发自动重绘。

### 阶段四：后期排版与合成 (Post-production Pipeline)
* **Agent 7 - 嵌字排版师 (Typesetter Agent)：** 作为一个灵活的路由与后期模块。若用户选择“AI 嵌字”，则直接校验 Nano Banana 2 产出的原生图文结合画面；若用户选择“兼容模式”，则指令画师输出无字净版图，并在前端或独立图层上程序化生成气泡、文本和矢量漫符特效，以兼容其他不支持原生嵌字的图像模型。
* **Agent 8 - 拼版总集 (Compositor Agent)：** 将背景图、角色图、特效图层与文字图层（如有）按预设 2x2 或 1x4 模板合并，输出最终成品及项目工程文件。

## 四、 核心数据契约 (Data Contracts)
系统内部各模块的数据流转严格依赖标准化的 JSON Schema，主要包含以下三种核心数据结构：
1. `Character_Profile.json`：采用“基础核心（Base）+ 扩展槽位（Outfits）”模式，分离肉体特征与服装资产。
2. `Script_Outline.json`：规范剧情逻辑，包含 `mode` 字段以区分 `standalone`（独立）或 `serialized`（连载），并记录连载的话数进度。
3. `Storyboard_Render_Payload.json`：包含 `export_type` 字段（`native_text` 或 `clean_plate`），严格隔离给绘画 API 的指令和给排版程序的独立图层指令。

## 五、 开发与联调规范

* **配置文件管理：** 在服务器端进行配置调试或审查生成的 JSON 资产时，为保证效率与一致的开发体验，统一使用 `vim` 进行文本编辑。
  ```bash
  # 示例：后端开发联调时快速修改分镜测试数据
  vim mock_storyboard_payload.json
  ```
* **接口联调：** 建议前后端分离开发，前端初期可依赖后端提供的 Mock JSON 数据，优先跑通“聊天式预览”的交互逻辑和无字/有字版本的切换逻辑。
